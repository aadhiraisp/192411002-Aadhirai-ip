Everything on this page is doing double duty

Built to answer the standards checklist the team raised during development — not just describe the fixes, but demonstrate them live on the page.

01 · Promo without a video file

Rather than an embedded <video> pointing at a stock clip, the hero is a live 10-second looping SVG/CSS animation — lighter than video, accessible via role="img" + a text alternative, and it visualizes the actual product instead of stock footage.

02 · Registration form, sent securely

The form below uses method="post", not get — credentials never belong in a URL or browser history. Combined with HTTPS, the body is encrypted in transit end to end.

03 · Semantic navigation

The header uses a real <nav> wrapping a <ul> of links, labelled with aria-label="Primary" — not a <div> soup styled to look like a menu, so assistive tech announces it correctly.

04 · Valid XML config

Config below is corrected: one root element, properly closed and nested tags, quoted attributes, and no bare &. See the diff in the config section.

05 · Correct protocol

Every endpoint is served over HTTPS (TLS 1.3), never plain HTTP — the handshake animation above is literally that negotiation happening before any data moves.

XML config: before and after

The file the team flagged had three classic well-formedness errors. Corrected version below.

<!-- before: unclosed tag, unquoted attribute, bare ampersand, two roots -->
<config>
  <service env=production>
    <name>Handshake API & Gateway</name>
    <port>8443
  </service>
</config>
<logging level="debug"/>

<!-- after: single root, closed + nested tags, quoted attrs, escaped entity -->
<config>
  <service env="production">
    <name>Handshake API &amp; Gateway</name>
    <port>8443</port>
  </service>
  <logging level="debug"/>
</config>
