1. SOAP-Based Hospital Management Web Service

A hospital management system can use a SOAP-based web service to exchange patient information between departments such as reception, laboratory, pharmacy, billing and medical records.

Main Operations

Operation Purpose
addPatient() Register a new patient
getPatient() Retrieve patient information
scheduleAppointment() Schedule an appointment
getMedicalRecords() Retrieve medical records
updateMedicalRecord() Update medical information
cancelAppointment() Cancel an appointment

SOAP Message Structure

SOAP Envelope
Root element of every SOAP message.
SOAP Header
Contains security, authentication and transaction information.
SOAP Body
Contains the actual request or response data.

SOAP Request Example

<soap:Envelope
    xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/"
    xmlns:h="http://hospital.example.com/">

    <soap:Header>
        <h:Security>
            <h:Username>hospitalClient</h:Username>
            <h:Token>ABC123</h:Token>
        </h:Security>
    </soap:Header>

    <soap:Body>

        <h:AddPatient>

            <h:PatientID>P101</h:PatientID>
            <h:Name>Arun Kumar</h:Name>
            <h:Age>45</h:Age>
            <h:Gender>Male</h:Gender>
            <h:Department>Cardiology</h:Department>

        </h:AddPatient>

    </soap:Body>

</soap:Envelope>

Data Exchange

Hospital Client
→
SOAP Request
→
SOAP Server
→
Database
→
SOAP Response
→
Client
Why SOAP? SOAP is suitable for hospital systems because it provides structured XML communication, interoperability, security through standards such as WS-Security, reliable messaging, and standardized fault handling.

2. WSDL Structure for an Enterprise Web Service

WSDL stands for Web Services Description Language. It is an XML-based language used to describe the interface, operations, messages, communication protocol and endpoint of a web service.

Main WSDL Components

Component Purpose
Types Defines data types
Message Defines input and output messages
PortType Defines available operations
Binding Defines communication protocol
Service Defines actual service endpoint

WSDL Structure

<definitions>

    <types>
        <!-- Data types -->
    </types>

    <message name="GetDataRequest">
        <!-- Input message -->
    </message>

    <message name="GetDataResponse">
        <!-- Output message -->
    </message>

    <portType name="EnterprisePortType">

        <operation name="getData">
            <input message="tns:GetDataRequest"/>
            <output message="tns:GetDataResponse"/>
        </operation>

        <operation name="updateData">
            <input message="tns:UpdateDataRequest"/>
            <output message="tns:UpdateDataResponse"/>
        </operation>

    </portType>

    <binding name="EnterpriseSoapBinding"
             type="tns:EnterprisePortType">

        <soap:binding
            style="document"
            transport="http://schemas.xmlsoap.org/soap/http"/>

    </binding>

    <service name="EnterpriseService">

        <port
            name="EnterpriseSoapPort"
            binding="tns:EnterpriseSoapBinding">

            <soap:address
                location="https://example.com/EnterpriseService"/>

        </port>

    </service>

</definitions>

WSDL Flow

Types
→
Messages
→
PortType
→
Binding
→
Service
Importance: WSDL acts as a contract between the service provider and service consumer. It allows external systems to understand available operations, required data, protocols and endpoints.

3. Debugging SOAP Communication Problems

SOAP communication problems may occur because of invalid XML, incorrect namespaces, wrong endpoints, authentication errors, incorrect SOAPAction values, database problems or network timeouts.

Common Problems

Problem Description
XML Formatting Invalid or incorrectly structured XML
Namespace Error Incorrect XML namespace
Endpoint Error Incorrect service URL
SOAPAction Error Operation does not match expected action
Authentication Error Invalid credentials or security token
Database Error Database unavailable or query failure
Timeout Server or network response is too slow

Debugging Process

Check Endpoint
→
Validate XML
→
Check Namespace
→
Check WSDL
→
Check Server
→
Check Database

SOAP Fault Handling

<soap:Fault>

    <faultcode>soap:Server</faultcode>

    <faultstring>
        Unable to retrieve patient records
    </faultstring>

    <detail>
        Database connection failed
    </detail>

</soap:Fault>

Validation Algorithm

START

1. Check the SOAP endpoint.

2. Validate XML syntax.

3. Check SOAP Envelope.

4. Check SOAP Header.

5. Check SOAP Body.

6. Verify XML namespaces.

7. Compare request with WSDL.

8. Verify SOAPAction.

9. Check authentication.

10. Check server logs.

11. Check database connectivity.

12. Check response.

13. IF SOAP Fault exists THEN
        Read fault code.
        Read fault message.
        Log the error.
        Handle the error.
    ELSE
        Process the successful response.
    END IF

END
Result: Correct endpoint, valid XML, correct namespaces, proper authentication, WSDL validation, logging and SOAP Fault handling ensure reliable SOAP communication.

4. XML Parsing and Database Data Processing

XML parsing is used to read structured XML data. The parser loads the document, identifies the root element, traverses child nodes and extracts the required information.

XML Parsing Algorithm

START

1. Load the XML document.

2. Check whether the XML file exists.

3. Parse the XML using an XML parser.

4. Check whether the XML is valid.

5. Get the root element.

6. Traverse the child nodes.

7. FOR each node DO

       Read the element name.

       Read its value or attribute.

       IF child elements exist THEN
           Traverse the child elements recursively.
       END IF

   END FOR

8. Store the extracted information.

9. Display the extracted data.

10. Close the XML document.

END

Example XML Data

<users>

    <user>
        <id>101</id>
        <name>Arun</name>
        <email>arun@gmail.com</email>
    </user>

    <user>
        <id>102</id>
        <name>Priya</name>
        <email>priya@gmail.com</email>
    </user>

</users>

Database Retrieval Algorithm

START

1. Load database driver.

2. Establish database connection.

3. Check connection status.

4. Create SQL SELECT query.

5. Create Statement or PreparedStatement.

6. Execute the SQL query.

7. Store the result in ResultSet.

8. IF records exist THEN

       WHILE records are available DO
           Read required columns.
           Store values.
           Display values.
       END WHILE

   ELSE

       Display "No records found".

   END IF

9. Close ResultSet.

10. Close Statement.

11. Close Database Connection.

END
XML parsing allows hierarchical data to be processed correctly, while database retrieval allows applications to obtain and display persistent information stored in relational databases.

5. PHP Form Validation

PHP validation ensures that information entered into a web form is complete, correctly formatted and suitable for processing before it is stored or submitted.

Validation Algorithm

START

1. Receive the submitted form data.

2. Initialize an empty error list.

3. Read Name, Email and Password.

4. Remove unnecessary spaces.

5. Check Name.

   IF Name is empty THEN
       Add "Name is required".
   END IF

6. Check Email.

   IF Email is empty THEN
       Add "Email is required".

   ELSE IF email format is invalid THEN
       Add "Enter a valid email address".
   END IF

7. Check Password.

   IF Password is empty THEN
       Add "Password is required".

   ELSE IF password length is too short THEN
       Add "Password is too short".
   END IF

8. Check the error list.

9. IF errors exist THEN

       Display error messages.
       Do not process the form.

   ELSE

       Accept the data.
       Process or store the data.
       Display success message.

   END IF

END

Validation Flow

User Input
→
Empty Check
→
Email Check
→
Password Check
→
Check Errors

PHP Validation Example

<?php

$name = trim($_POST["name"]);
$email = trim($_POST["email"]);
$password = $_POST["password"];

$errors = array();

if (empty($name)) {
    $errors[] = "Name is required";
}

if (empty($email)) {
    $errors[] = "Email is required";
}
else if (!filter_var($email, FILTER_VALIDATE_EMAIL)) {
    $errors[] = "Invalid email format";
}

if (empty($password)) {
    $errors[] = "Password is required";
}
else if (strlen($password) < 8) {
    $errors[] = "Password must contain at least 8 characters";
}

if (!empty($errors)) {

    foreach ($errors as $error) {
        echo $error . "<br>";
    }

}
else {

    echo "Form submitted successfully.";

}

?>
Result: PHP validation prevents incomplete or incorrectly formatted data from being processed and ensures that only valid input is accepted.
